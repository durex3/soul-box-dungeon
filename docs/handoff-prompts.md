# 换电脑与各角色接手提示词

> 更新：2026-10-31。复制所需角色的代码块到新会话，并替换尖括号占位符。本文是交接入口，实时进度以[status](status.md)、[backlog](backlog.md)和对应任务说明为准，不以聊天记忆为准。

## 1. 从这里开始

1. 新电脑克隆仓库，已有副本则先检查工作区并同步main。
2. 完成下文环境检查。
3. 负责人指定本会话角色，复制该角色提示词。默认开发规则见[AGENTS.md](../AGENTS.md)，项目经理流程见[pm-guide](pm-guide.md)。
4. 项目经理先确认进度、选任务并写说明；负责人确认后登记待开发；开发完成后交项目经理独立验收。

| 角色 | 职责 | 边界 |
|---|---|---|
| 负责人（用户） | 决定方向、设计取舍、任务范围与试玩结论 | 不把开发自检当作项目经理验收 |
| 项目经理 | 写任务、验收、合并、维护docs | 不写玩法代码、不出图、不替开发修问题 |
| 开发 | 按任务实现、测试、自检、提交任务分支 | 不合并main、不擅改设计和docs |
| 测试 | 独立复现、回归、故障检查、给出证据 | 不代修、不自行合并或批准设计 |
| 美术 | 按任务出图、交原生源、导出及自检 | 不把灰盒当正式锚点、不修改玩法 |

当前执行分工是“负责人＋项目经理＋Codex开发/测试/美术”。测试和美术提示词用于负责人明确分配的专门会话，**不意味着自动启动多个代理或允许多个会话同时改同一分支**。角色由职责决定，不绑定某个模型名称。

macOS/Linux shell示例（替换本机路径）：

```bash
export GODOT_BIN="/Applications/Godot.app/Contents/MacOS/Godot"
export ASEPRITE_BIN="/Applications/Aseprite.app/Contents/MacOS/aseprite"
python3 tools/run_tests.py
python3 tools/art_check.py
```

Windows PowerShell示例（替换本机路径和Python命令）：

```powershell
$env:GODOT_BIN = "D:\Tools\Godot\Godot.exe"
$env:ASEPRITE_BIN = "C:\Program Files\Aseprite\Aseprite.exe"
py -3.9 tools/run_tests.py
py -3.9 tools/art_check.py
```

这只是路径配置示例，不代表全部独立图形脚本已在Windows验收。既有验收工具可能含`/private/tmp`输出路径；新平台先读任务工具的参数与代码，按任务授权做必要适配并保留断言，不能把路径错误当作玩法失败。

`tools/run_tests.py`会先导入，再运行测试。手动调用Godot也须先导入，并用Python `subprocess.run(..., timeout=...)`限制运行时间，防止脚本错误后挂住。MCP的run_project启动后应单独get_debug_output，再stop_project；不能把启动无错当成交互验收完成。工具未加载就如实报告，可用限时命令行完成适用检查，不捏造MCP或实物操作记录。

### Git不会迁移的内容

- 旧会话上下文、插件/技能安装、MCP客户端配置、环境变量及GitHub SSH认证。
- `.godot/`导入缓存；新电脑由Godot重新生成，不能提交缓存补问题。
- `/private/tmp/...`及其他本机临时截图/探针/日志；文档里的旧绝对路径只作历史证据。持久证据见`tools/acceptance/`，复验时重跑对应工具生成本机证据。
- 系统安装的字体、Godot/Aseprite/Python程序和硬件性能。性能结论须记录新机器配置，不能照抄M1测量。

## 9. 验收、返修及跨电脑续做

项目经理验收交办：

```text
开发已完成RK-<编号>，分支rk-<编号>，提交<完整哈希>。请以项目经理身份独立验收：先读任务和验收记录，在单独工作树复跑标准、故障及额外检查。通过后按pm-guide合并并更新docs；失败则写退回记录，不代修。保留工作区已有修改。
```

开发返修交办：

```text
RK-<编号>被退回。先读AGENTS.md和docs/tasks/rk-<编号>.md末尾最新退回记录。切回原rk-<编号>分支，合入最新main，逐条返修并重跑相关检查，汇报每条修改及提交哈希。不要重建无关分支或改写历史。
```

若原分支已被删除或仅在另一电脑本地，先找指定提交/远程任务分支，让项目经理确认恢复方式，不凭空换任务编号。已合并后发现问题也可同编号复验退回，已有main合并不自动回滚；记录哪个退回/通过结论取代了旧结论。

跨电脑继续未完任务时，旧电脑先保留并说明未提交文件、任务分支、最后提交、未完成检查；负责人授权后把任务分支推到origin，新电脑fetch并检出该分支继续。**只推main不会带走另一个本地任务分支或未提交修改**。未验收任务不得为了迁移而直接合进main。

要求同步GitHub：

```text
把本次已完成的指定分支推送GitHub。先检查git状态和远程，fetch核对差异；不force push，不覆盖本地改动或不明远程历史。推送后核对远端提交与本地一致，报告分支及哈希。
```

新电脑只做接手检查时，不自动推进RK010或RK086，不新建任务编号，不合并未验收分支。先确认角色和已授权任务，避免把交接清单当作全部开工指令。
