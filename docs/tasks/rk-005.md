# RK-005 单局种子和子随机流

| 项 | 内容 |
|---|---|
| 优先级 / 里程碑 | P0 / M1 |
| 依赖 | RK-003（已合并） |
| 分支 | `rk-005` |

## 目标
按 architecture 4.5、4.6 节，给模拟层提供唯一的随机来源 `RunRng`：一个单局种子派生出刷怪、商店、掉落、升级 4 个子流，互不影响。RK-046 刷怪、RK-052 升级、RK-055 商店、RK-059 宝箱都从这里取随机数；RK-081 回放靠它复现一局。

本任务只做随机流和配套的分层检查，不接入 `Sim`（`Sim` 还不存在，由后续任务创建时持有一个 `RunRng`）。

## 要做的

### 1. `game/sim/core/run_rng.gd`
`class_name RunRng`，`extends RefCounted`。

```gdscript
var run_seed: int                      # 只读约定：创建后不改
var spawn: RandomNumberGenerator
var shop: RandomNumberGenerator
var loot: RandomNumberGenerator
var upgrade: RandomNumberGenerator

func _init(seed_value: int) -> void
static func derive_seed(seed_value: int, stream_name: StringName) -> int
```

- 4 个子流用具名成员，不用 `stream("shop")` 这种按字符串取的写法，拼错名字时解析阶段就会报错
- `_init` 里为每个子流 `RandomNumberGenerator.new()`，`seed` 设为 `derive_seed(seed_value, 流名)`。流名依次为 `&"spawn"`、`&"shop"`、`&"loot"`、`&"upgrade"`
- 任何整数都是合法种子，包括 0 和负数

### 2. 派生算法（必须完全照做，后续回放和每日挑战依赖它不变）
1. 对流名的 UTF-8 字节做 64 位 FNV-1a：初值 `0xCBF29CE484222325`，每个字节先异或、再乘 `0x100000001B3`
2. 把结果和 `seed_value` 异或
3. 用 SplitMix64 的终结步骤打散：

```
x = x + 0x9E3779B97F4A7C15
x = (x ^ (x >>> 30)) * 0xBF58476D1CE4E5B9
x = (x ^ (x >>> 27)) * 0x94D049BB133111EB
x = x ^ (x >>> 31)
```

`>>>` 是逻辑右移（高位补 0）。所有运算都在 64 位上回绕。

GDScript 的写法要点（项目经理已在 Godot 4.7.2 实测，见 architecture 第 12 节）：
- `int` 是 64 位有符号整数，加法和乘法溢出时回绕，可以直接用
- `>>` 是算术右移，负数高位补 1。要自己写逻辑右移：`(x >> n) & ((1 << (64 - n)) - 1)`
- 常量写成有符号十进制，后面注释写原来的十六进制，例如 `const MIX_ADD: int = -7046029254386353131  # 0x9E3779B97F4A7C15`

种子 12345 的正确结果（项目经理用 Python 参考实现算出，并和 Godot 实测结果核对过）：

| 流 | `derive_seed(12345, 流名)` |
|---|---|
| `spawn` | `7640713538129709433` |
| `shop` | `5310988902323854553` |
| `loot` | `-244990251510703615` |
| `upgrade` | `49347111058617004` |

### 3. 分层检查补两条（`tools/lint_layers.py`）
architecture 4.6 节第 1 条要求模拟层只用 `RunRng` 的子流。现有检查只拦全局 `randf()` 这类函数，拦不住自己新建随机数生成器。在 `sim/` 的检查里加：

| 报错条件 | 例外 |
|---|---|
| 出现 `RandomNumberGenerator.new(` | `sim/core/run_rng.gd` 本身 |
| 出现 `randomize(`，包括 `rng.randomize()` 这种成员调用 | 无。`randomize()` 用系统时间做种子，会破坏确定性 |

- 规则说明写清原因，例如 `随机数生成器只能在 RunRng 里创建`
- 例外按文件路径判断，不按 `class_name`
- 现有的 `tools/test_lint_layers.py` 把 `rng.randomize()` 列为合法写法（RK-003 时的规则）。这次规则变了，把它从合法列表移到违规列表。这是收紧检查，不算放宽测试
- 其余规则和 RK-003 一样，不要改

### 4. 测试
`game/tests/sim/core/test_run_rng.gd`，必须有的用例（方法名自定，汇报里按顺序列出）：
1. **同一种子两次**：种子 12345 建两个 `RunRng`，4 个子流各取前 1000 个 `randi()`，两边逐个相等（backlog 验收标准）
2. **子流互不影响**：建两个种子相同的 `RunRng`，其中一个先从 `shop` 多取 100 个数，然后两边的 `spawn` 前 1000 个数相同。对 `loot`、`upgrade` 也各测一次（backlog 验收标准）
3. **派生结果固定**：`derive_seed(12345, 流名)` 等于第 2 节表里的 4 个值
4. **子流各不相同**：同一种子下，4 个子流的种子两两不同，前 10 个数也不完全相同
5. **种子不同结果不同**：种子 1 和种子 2 的 `spawn` 前 10 个数不完全相同
6. **边界种子**：0、-1、`9223372036854775807`、`-9223372036854775808` 都能创建，不报错，且同一种子两次结果相同
7. **引擎没变**：`RandomNumberGenerator` 设 `seed = 42` 后前 3 个 `randi()` 为 `492690617, 1919685028, 3561993920`（项目经理在 Godot 4.7.2 实测）。以后升级 Godot 时这个用例失败，说明旧的回放会失效，要先告诉项目经理

`tools/test_lint_layers.py` 补：`RandomNumberGenerator.new()` 在 `sim/` 其他文件里报错、在 `sim/core/run_rng.gd` 里不报错、写在注释里不报错；`randomize()` 和 `rng.randomize()` 都报错；`data/` 不受这两条影响。

### 遗留：分层检查没拦住的全局随机写法（不算本任务的问题）
architecture 第 66 行禁止模拟层调用全局随机函数，但 RK-003 和本任务只列了 `randf`、`randi`、`randf_range`、`randi_range`、`randomize`。下面这些写法目前在 `sim/` 里不报错，都会用到全局随机状态，破坏确定性：

- `seed(42)`、`rand_from_seed(1)`、`randfn(0.0, 1.0)`
- `Array.shuffle()`、`Array.pick_random()`（数组自带的方法，用的是全局随机）
- `var C = RandomNumberGenerator` 再 `C.new()`（把类存进变量绕开检查，风险低）

另开一个小任务补规则，项目经理先在 architecture 4.6 节把这些写法列清楚。
