# RK-004 数据表和校验

| 项 | 内容 |
|---|---|
| 优先级 / 里程碑 | P0 / M1 |
| 依赖 | RK-003（已合并） |
| 分支 | `rk-004` |

## 目标
把原型要用的数值从 GDD 录进 `game/data/`，并写好校验。数据写错时，测试和启动都要拦下来，并报出哪张表、哪一行、哪个字段。后续的玩法任务（RK-014、RK-021、RK-025、RK-041、RK-046、RK-052、RK-057 等）都从这里读数值。

本任务只录数据、写校验，不写使用这些数据的玩法代码。

## 通用约定
- 格式按 architecture 第 5 节：每张表一个文件，`class_name XxxTable`，`extends RefCounted`，只放 `const SCHEMA`、`const ROWS` 和静态校验函数
- 单位：距离和速度用格（1 格 = 16 像素），时间用秒，百分比写成小数（5% 写 `0.05`）
- `id` 用 `StringName`，只含小写字母、数字、下划线。引用其他行的字段名以 `_id` 结尾，没有引用时写 `&""`
- 枚举值（标签、武器类型等）也用 `StringName`，取值见第 7 节 `balance.gd`
- 每组数据前用注释注明 GDD 出处，例如 `# GDD 7.2 节`
- 下文给出了所有 id，按给定的 id 录入。后续任务和验收都按这些 id 查

### 公共校验 `data/table_util.gd`
`class_name TableUtil`，提供：

```gdscript
## schema 形如 { "id": TYPE_STRING_NAME, "damage_t1": TYPE_FLOAT, "tags": TYPE_ARRAY }
static func check_rows(table: String, rows: Array[Dictionary], schema: Dictionary) -> PackedStringArray
```

逐行检查，每个问题一条错误：
- 缺少 schema 里的字段；出现 schema 里没有的字段（防止字段名拼错）
- 字段类型不对。`TYPE_FLOAT` 字段允许写整数，`TYPE_INT` 字段不允许写小数
- `id` 格式不对、`id` 重复、`name_cn` 为空

错误文字必须包含表名、行的 `id`（没有 `id` 时写行号）和字段名，例如 `SoulTable fireball: 缺少字段 cooldown`。

每张表的 `validate(rows)` 先调用 `check_rows()`，再做本表检查（见下文各表）。已经报了缺字段或类型错误的行，跳过本表检查，避免同一个问题连报多条。

校验函数的两条硬要求：
- 只返回错误列表，不调用 `push_error()`，也不打印 `ERROR`。否则测试坏数据时，`run_tests.py` 会把输出里的报错行判为失败
- 读字段一律先 `has()` 或用 `get()`。坏数据缺字段时，直接 `row["x"]` 会运行时报错

只录原型范围（GDD 20 节）。后续任务需要新字段时，由那个任务自己加。

### 8. 跨表检查 `data/data_check.gd`（`DataCheck`）

```gdscript
## 各表各自的 validate()，加上 Balance 自检和跨表引用检查，用真实数据
static func validate_all() -> PackedStringArray
## 只做跨表引用检查，参数传入，方便测试传坏数据
static func check_refs(souls: Array[Dictionary], relics: Array[Dictionary],
		enemies: Array[Dictionary], waves: Array[Dictionary]) -> PackedStringArray
```

`check_refs()` 检查：
- 魂匣的 `evolve_relic_id` 在遗物表里存在，并且那个遗物的 `evolves_soul_id` 指回这个魂匣
- 遗物的 `evolves_soul_id` 在魂匣表里存在，并且那个魂匣的 `evolve_relic_id` 指回这个遗物
- 敌人的 `first_wave` 不超过波次表最后一段的 `last_wave`
- 引用字段为 `&""` 的行不检查（比如没有进化的魂匣、通用遗物）

`validate_all()` 另外检查 `Balance` 自身：`STAT_CAP`、`STAT_FLOOR` 的键都在 `STAT_BASE` 里；`RELIC_EXTRA_MODS` 和 `STAT_BASE` 没有重复的键；`UPGRADE_QUALITY_BASE` 的和为 1（误差 0.0001）。

### 10. 测试 `game/tests/data/`
每张表一个测试文件，加上 `test_table_util.gd` 和 `test_data_check.gd`。坏数据用 `XxxTable.ROWS.duplicate(true)` 复制后再改，`const` 数组本身是只读的。

必须有的用例（方法名自定，汇报里按下面的顺序列出）：
1. 真实数据：每张表的 `validate(ROWS)` 和 `DataCheck.validate_all()` 都返回空列表
2. 行数：魂匣 12、主武器 8、遗物 20、敌人 8、波次 2、升级选项 18
3. `TableUtil`：缺字段、多出字段、类型错误、`id` 格式不对、`id` 重复、`name_cn` 为空，各报 1 条以上错误；`TYPE_FLOAT` 字段写整数不报错，`TYPE_INT` 字段写小数报错
4. 错误文字包含表名、行的 `id` 和字段名
5. 缺字段的行交给 `validate()` 不会运行时报错（`run_tests.py` 会抓 `SCRIPT ERROR`），并且同一个缺字段只报 1 条
6. 第 1-6 节每一条"本表检查"，至少 1 个违反它的用例
