# RK-041 敌人基础

> 项目负责人已确认：敌人状态、出生/移除命令、只读查询、基础追击及软分离；普通敌人暂统一8px半径，200夹具最近邻最小≥8px、至少95%≥14px；不做具体敌种攻击或死亡奖励。

## 目标
按backlog RK-041、architecture 3/4节及GDD 11.3/11.4/14节建立EnemyState和数据驱动基础运动。RK042/043/044/048再接具体敌种、攻击及精英行为，RK046接波次刷怪，RK024使用位置索引索敌。

## 已确认的设计限定
- 本任务8种普通敌人暂统一逻辑半径8px，放入数据配置；不是按PNG画布推断。专属敌种/精英任务需要变更体型时另审，不把本次圆形标记当正式敌种外观。
- 分离采用轻量位置修正，允许拥挤时少量交叠；不承诺严格刚体零穿透。200只标准夹具最终最近邻距离：最小至少8px，至少95%的敌人最近邻距离≥14px（直径16px）；基线无分离时必须明显失败。此为已确认验收目标，不是已实测的引擎保证。
- 分离修正是独立拥挤挤开位移，可额外改变位置，不伪装成敌人自身移速增益；孤立追击严格遵守表中速度。没有伤害/玩家推挤判定，敌人可到达玩家中心，彼此由分离保持分散。

## 要做的

### 1. 数据和状态
- 新增 `game/data/enemy_config.gd`，EnemyConfig继承RefCounted：DEFAULT_RADIUS=8.0；分离迭代数等调度常量集中放此处（最多8轮/逻辑步，具体值提交说明给实测依据）。不复制EnemyTable数值。
- 新增 `game/sim/entities/enemy_state.gd`，EnemyState继承RefCounted，外部只读：entity_id:int、enemy_type:StringName、position:Vector2、radius:float、max_hp:float、hp:float、damage:float、move_speed:float（像素/秒）、xp:float、spawn_wave:int、danger_level:int。
- 数据构建逻辑放在同目录 `enemy_factory.gd` 或EnemyState静态构造方法；从EnemyTable按id读取并复制必要值，不修改常量表、共享Dictionary或其他实体。
- 生命=基础hp×(1+Balance.ENEMY_HP_GROWTH×(wave-1))×危险生命倍率；伤害同式使用ENEMY_DAMAGE_GROWTH及危险伤害倍率；经验=基础xp×(1+ENEMY_XP_GROWTH×(wave-1))，不受危险系数影响。初始hp=max_hp，保留浮点，不擅自取整。
- move_speed=表中格/秒×ArenaConfig.TILE_PX，不随波次成长；dash_speed/child_xp等保留原表，不在本任务实现冲刺、分裂或射手保持距离。
- GDD14：危险0级生命/伤害均1；1—5级生命1.15、伤害1.10，之后不再叠乘。若Balance无此常量，允许仅追加对应具名常量及数据核对测试，不扩展危险模式系统。

### 2. 正式入口、身份与生命周期
- 扩展RunState，新增 `enemies: Array[EnemyState]`，只读约定，按entity_id升序；玩家保留ID0（允许给PlayerState新增只读entity_id=0），普通实体由Sim单局计数器从1递增，不复用已移除ID，不从数组索引取身份。
- 新增 `game/sim/core/command.gd`（Command，RefCounted），本次只定义Kind.SPAWN_ENEMY、DESPAWN_ENEMY及类型化payload字段：enemy_type、position、wave、danger_level、entity_id。命令是外部意图，不让表现层直接写state。
- Sim增加正式 `apply(cmd: Command) -> Array[SimEvent]`：出生按表构建实体、位置用ArenaBounds.clamp_position约束整圆，加入敌人数组和正式SpatialHash；移除同步删除状态及索引。apply只在两次step之间调用，不在实体遍历中删数组。
- SimEvent只增加本次需要的Kind.SPAWNED、DESPAWNED、COMMAND_FAILED，字段kind/entity_id/reason；返回整数ID，不传EnemyState/Node。SPAWNED/DESPAWNED表示状态已完成对应改变，不冒充伤害死亡，不发经验奖励。
- 未知敌人id、wave<1、危险等级不在0—5、移除不存在ID、未知命令：返回COMMAND_FAILED，状态/计数器/索引不变，不push_error。合法输入坐标有限；无需为NaN/INF构建通用校验框架。
- 出生命令不强制first_wave筛选，这是后续刷怪器职责；探针可直接创建任意现有敌种。暂不做自动刷怪、300上限强化、死亡结算或存档。
- 索引由Sim持有，提供只读用途的 `query_enemies(center: Vector2, radius: float) -> Array[int]`，委托正式SpatialHash，仅返回敌人中心点ID。此为本任务已确认新增的只读查询接口；写操作仍只通过step/apply。

### 3. 基础追击与确定性软分离
- Sim.step先按原逻辑更新玩家，再按enemy_id升序更新敌人；有敌人时仍只走Sim.DT，不读渲染delta、Time、Input、物理、窗口或Node。
- 每只先向本帧玩家位置直线move_toward，最大自主位移move_speed×DT；距离不足一步时停在目标，不越过目标振荡。目标正好同点时安全，不产生NaN。
- 追击位置提交后做分离修正，使用正式SpatialHash邻域候选，不做每只遍历全体的生产O(N²)筛选。候选范围至少radius_i+当前最大敌人radius；按距离精筛且排除自身，候选和实体处理顺序固定升序。
- 建议方法：每轮每对i<j只处理一次，重叠距离的一半沿两圆连线分别向外修正，然后夹回场地；同步刷新空间索引。不得一边依据旧索引精筛、一边用新坐标提交而漏清旧桶。可每轮统一重建一次索引，不可每次查询重新建网格。
- 两圆完全同点必须有确定性的反向解开方向，不调用随机；可从有序ID对整数哈希映射8个固定单位方向。禁止所有同点对共用同一方向导致固定直线挤压，映射写清并测试重复可复现。
- 迭代有界（最多8轮），具体实现允许开发依据下面的量化标准选择；提交记录实际迭代数、拥挤指标与代价。未达到标准就汇报问题，不降低半径、删敌人、传送到预设阵列或放宽断言。
- 每帧最后索引与最终状态一致，移除/重建不残留；分离不修改hp/damage/xp或随机流状态。外部不直接调用内部运动辅助对象修改状态。

### 4. 无界面测试
`game/tests/sim/`新增正式入口和基础构建/分离测试，按顺序汇报：
