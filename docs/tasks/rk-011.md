## 目标
按 backlog RK-011、GDD 11.2、style-bible 1.1/2.1/11/15 节实现封闭竞技场的几何边界和灰盒画面。解除 RK-012 玩家移动的阻塞，后续 RK-041 敌人移动也复用同一套边界约束。

模拟层不用 Godot 物理，表现层不判定碰撞。当前没有玩家和敌人，以两种测试标记验证共用的边界函数；真实实体在各自任务中接入，不提前实现实体系统。

### 本次已确认的口径
- 1280×720 **包含**四周 32 像素厚围墙；可活动内矩形为 `(32,32)` 至 `(1248,688)`，尺寸 1216×656。
- 暂用测试标记验证封闭性。后续 RK-012 和 RK-041 必须在每次移动后调用本任务的约束函数；本任务不宣称已验证尚未存在的真实实体。

## 要做的

### 1. 数据层尺寸
新增 `game/data/arena_config.gd`，`class_name ArenaConfig`，继承 RefCounted，只含以下常量及出处说明，不增加数据表或跨表校验：
```gdscript
const TILE_PX: int = 16
const OUTER_SIZE: Vector2i = Vector2i(1280, 720)
const WALL_TILES: int = 2
```
尺寸从这里读取；模拟层和表现层不各写一套。来源分别为 style-bible 1.1、11 和本任务经确认的外框口径。无需修改已有数据表或 Balance。

### 2. 模拟层边界
新增 `game/sim/core/arena_bounds.gd`，`class_name ArenaBounds`，继承 RefCounted，公开静态接口：
```gdscript
static func outer_rect() -> Rect2
static func play_rect() -> Rect2
static func clamp_position(position: Vector2, radius: float = 0.0) -> Vector2
static func contains_circle(position: Vector2, radius: float = 0.0) -> bool
```
- outer_rect：原点 (0,0)，大小 OUTER_SIZE；play_rect 从四边各缩进 WALL_TILES*TILE_PX。
- 合法输入为有限位置、有限半径，且 `0 <= radius <= play_rect().size.y / 2`。无需为任意 NaN/无穷输入扩展工具，本任务测试使用合法输入。
- clamp_position：把圆心的 x/y 分别夹到 `[play_rect.position + radius, play_rect.end - radius]`；允许与内墙接触，不能穿入墙体。返回新位置，不持有或修改实体。
- contains_circle：使用相同的半径范围和**包含边界**的比较，判断整个圆是否在活动区域；不能直接使用 Rect2.has_point，因为 Godot 排除矩形的右/下端点。
- 玩家和敌人以后都调用同一接口。不要按名称、实体类型或阵营做例外，也不用 Area2D/StaticBody2D/CollisionShape2D。

### 3. 灰盒场景
新增 `game/view/battle/arena_view.gd` 和同名 `.tscn`，`class_name ArenaView`，继承 Node2D。
- 只读 ArenaConfig/ArenaBounds，用 `_draw()` 和整数坐标绘制，不包含移动或边界判定。
- 四周连续围墙，厚度 32 像素，外框 1280×720；顶/底贯穿全宽，左/右填满剩余边，四角不留洞。
- 地面填充 `#1C1B26`；墙体 `#2E2A3A`（主色板“石头暗”，比地面亮一阶）。地面每 16 像素一条、宽 1 像素网格线；建议用墙色、alpha 0.25，最终渲染后的网格/地面亮度对比不超过 1.3:1。
- 先画地面及网格，再画墙体，网格不覆盖墙体。不加棋盘测试块、烛火、贴图、障碍物、AI 美术或动画。
- 保持默认 scale=(1,1)，不缩放地图去塞进一屏。640×360 视口只是竞技场的一部分。
- 本任务不接入 boot，也不改 project.godot。场景可在编辑器单独运行；如需看全图，在验收专用 SubViewport 里按 1280×720 原尺寸渲染，不修改生产分辨率。

### 4. 检查和画面证据
- 新增 `game/tests/sim/core/test_arena_bounds.gd`，继承 GdTest，测试纯边界函数。
- 新增 `tools/acceptance/rk011_probe.gd` 和 `rk011_verify.py`（Python 标准库），支持 GODOT_BIN、从任意 cwd 定位项目、先导入、每个 Godot 子进程 timeout 不超过 45 秒；检查退出码、ERROR:/SCRIPT ERROR、结果标志，失败必须非零退出。
- 默认 headless 检查正式场景可实例化、尺寸/颜色配置及共用边界调用，输出 `RK011: passed`。场景本身必须保持可独立运行。
- 另提供显式的画面导出模式（参数名称由开发写入提交说明）：使用有图形渲染的 Godot 进程，在 1280×720 SubViewport 中实例化正式 ArenaView 场景，等待实际绘制后导出 PNG。不得在 Python 里重画一张地图冒充运行截图。
- PNG 写到命令行指定的临时位置（默认 `/private/tmp/rk011-arena.png`），不提交生成图片。输出图宽高和用于取色的地面/网格/墙体采样坐标；至少覆盖四角、四边和内部非网格地面。提交说明列出运行命令。
- 本任务有画面标准，验收会查看这张实际渲染图及像素取色；纯程序绘图无独立美术资产，不新增 art 来源记录。

## 项目经理实测参考
2026-10-29，独立临时工程 Godot 4.7.2 实测，并用 Python 独立核对：
- play_rect = Rect2(32,32,1216,656)，end=(1248,688)，center=(640,360)。
- 半径 0：圆心范围 (32,32)—(1248,688)。
- 半径 8：圆心范围 (40,40)—(1240,680)。
- 半径 16：圆心范围 (48,48)—(1232,672)。
- `Rect2(32,32,1216,656).has_point(Vector2(1248,688))` 为 false，所以“碰墙合法”的判定必须显式包含右/下边界。

## 测试
汇报按顺序给测试方法名或探针命令输出：
1. outer_rect/play_rect 的位置、尺寸、中心和墙厚与上文参考值相等。
2. 半径 0/8/16：内部位置不变；分别越过左/右/上/下和四角，得到参考范围的对应端点；一次移动跨越整张地图也被夹回。
3. contains_circle：四边相切、四角相切为 true；从每边向外越过 0.001 像素为 false；clamp 后的结果始终为 true。不能只检查圆心。
4. 同一组位移分别作用于“玩家标记”（半径 8）和“敌人标记”（半径 16），循环 10000 步，每步调用正式 clamp_position 并检查 contains_circle。使用固定循环/固定输入，不依赖系统随机。
5. 在活动区域中心、半径取合法最大值 328 时能贴合上/下边，不发生 min>max；连续约束同一位置满足幂等性。
6. `python3 tools/run_tests.py` 完整通过，末行 `TESTS: N passed, 0 failed`。
7. `python3 tools/acceptance/rk011_verify.py` 退出 0，`RK011: passed`；按提交说明导出运行图，确认为 1280×720、32 像素围墙、正确地面色、16 像素网格、网格对比度不超标。
