## 目标
按 architecture 4.2 节，把渲染 delta 转为 60 Hz 的逻辑步数，提供后续 RK-012 玩家移动、RK-041 敌人和 RK-010 压测共用的驱动。暂停期间不积累待补帧时间。

当前没有 Sim、战斗场景或敌人。本任务只建立时间驱动和 `Sim.DT` 的最小定义，用测试专用匀速标记代替敌人验收。不提前实现 Sim.step/apply、RunState、输入、敌人或竞技场。

## 要做的

### 1. 模拟层时间常量
新增 `game/sim/core/sim.gd`，`class_name Sim`，继承 `RefCounted`。只定义 `const DT: float = 1.0 / 60.0`。不要添加临时的 step/apply 接口，后续任务扩展本类。

60 Hz 和 0.25 秒是 architecture 4.2 节规定的调度常量，不属于玩法硬编码；64 像素/秒和 10 秒只用于测试夹具，不写入生产模拟层。

### 2. 可独立检查的累加器
新增 `game/view/battle/fixed_step_clock.gd`，`class_name FixedStepClock`，继承 `RefCounted`。

公开接口：
```gdscript
const MAX_FRAME_TIME: float = 0.25
func advance(delta: float) -> int
func set_paused(value: bool) -> void
func reset() -> void
```

- 私有浮点累加器初值 0，暂停初值 false。
- advance：暂停时返回 0，且不累加；正常时累加 `clampf(delta, 0.0, MAX_FRAME_TIME)`，逐次扣除 Sim.DT，每扣一次计一步，返回总步数。
- 保留不足一帧的余数，不四舍五入，不在每次调用时清空。负 delta 按 0 处理。
- 单次最多纳入 0.25 秒，多出的时间丢弃，不在之后继续追赶。不要另设较低的补帧次数上限。
- 暂停和恢复保留暂停前的不足一帧余数；暂停期间的时间丢弃。reset 清空余数并恢复未暂停状态。
- 沿用 architecture 的直接比较/扣减算法即可，不要求加 epsilon 补帧；浮点边界参考“测试”节。

### 3. 真实运行驱动
新增 `game/view/battle/fixed_step_driver.gd` 和同名 `.tscn`，`class_name FixedStepDriver`，继承 `Node`，持有一个 FixedStepClock。

公开接口：
```gdscript
func configure(step_callback: Callable) -> void
func set_paused(value: bool) -> void
func reset() -> void
```

- 每次 `_process(delta)` 调用 clock.advance(delta)，按返回次数调用无参数的 step_callback。回调内部按 Sim.DT 推进模拟，不传渲染 delta。
- configure 必须在进入场景树前调用；没有有效回调时不启用处理，不积累时间。无需支持运行中换回调。
- 暂停、reset 委托累加器；不使用 `_physics_process` 再推进一次。
- 暂不接入 boot 场景。后续战斗任务负责配置回调并读取事件。

### 4. 自动检查与实际限帧探针
- 新增 `game/tests/view/battle/test_fixed_step_clock.gd`，继承 GdTest。直接调用纯 RefCounted 累加器，不依赖显示、节点、等待或真实时间。
- 这是对 architecture 9.3“表现层不写自动测试”的本任务限定例外：只测试纯时间计算辅助类；节点驱动用以下命令行探针检查。
- 在 `tools/acceptance/` 提交本任务专用 Godot 探针和 Python 标准库运行脚本，命名 `rk006_probe.gd`、`rk006_verify.py`。脚本从仓库任意工作目录调用都能定位 game，支持 GODOT_BIN；先导入，每个 Godot 子进程 timeout 不超过 45 秒。不要纳入常规 run_tests，避免每次多等 20 秒。
- 探针实例化正式 FixedStepDriver，configure 到自己的测试回调后加入场景树，使用真正的 `_process(delta)` 路径。每次回调令测试标记 `distance += 64.0 * Sim.DT`，同时计逻辑步数。禁止复制一套累加器到探针。
- 分别设置 Engine.max_fps 为 30、60，关闭垂直同步干扰；可 headless 运行，但必须使用真实时钟和实际调度，不传人为的 1/fps，不使用固定 FPS 模拟时间或 time_scale 修改。
- 用单调时钟从驱动开始处理前计时，至少运行 10 秒，在下一个处理完成后读取结果。输出 cap、实际秒数、渲染帧数、逻辑步数、distance；允许开始/结束处一个渲染帧的测量偏差。
- Python 检查两次距离差 / 60 fps 距离不超过 0.01；两次距离各在 640 的 ±1% 内，防止两次都不动也通过；检查渲染帧数/实际秒数在对应目标的 ±15% 内，证明限帧生效。机器负载导致达不到时报告原始结果，不能删掉这项检查。
- 子进程非零退出、超时、ERROR:/SCRIPT ERROR、缺少输出、非有限数或校验失败，脚本都以非零退出；所有检查通过才输出 `RK006: passed`。

## 测试
汇报按顺序给测试方法名或探针输出：
1. 零 delta 不推进；两个 DT/2 合为一步；多次调用保留余数。
2. 连续 300 次 1/30、600 次 1/60，分别得到 600 步，测试标记距离 640±0.000001。
3. 连续 1440 次 1/144，允许 599 或 600 步；相对 30 fps 的距离差不超过一帧距离 64*DT（比较容差 0.000001）。不得因追求正好 600 而改成每次调用至少推进一步。
4. 0.25 秒和 1.0 秒各用新时钟推进 15 步；之后 advance(0) 不继续补被丢弃的时间；负 delta 不使已有余数倒退。
5. 累加半帧、暂停、输入 10 秒、恢复后输入半帧，只得到一步；新时钟暂停期间始终 0 步；reset 后余数和暂停状态恢复初始值。
6. `python3 tools/run_tests.py` 全部通过，末行 `TESTS: N passed, 0 failed`。
7. `python3 tools/acceptance/rk006_verify.py`：真实 30、60 fps 两轮结果满足第 4 节约束，最终输出 `RK006: passed`。
