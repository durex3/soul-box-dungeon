## 目标
按GDD 8.1/9.1、backlog RK014及architecture模拟层约定，提供18属性的汇总、上下限和生命百分比减益计算，供RK015伤害、RK024魂匣及后续升级/遗物系统复用。字段严格对应Balance.STAT_BASE，不另造16字段模型。

## 已确认的计算限定
- 各来源的固定数值先求和，再按属性上下限截断；保留未经截断的原始来源。百分比属性沿用小数（0.5=+50%），不是50。
- 生命上限计算为 `max(10, (基础max_hp + 固定生命加值总和) * 每项生命减益因子之积)`；每项负max_hp_pct的因子为max(0,1+值)。先加固定值、再逐项乘减益、最后检查最低10，不在每一步夹取或四舍五入。
- 只支持18个基础属性和负值/零的max_hp_pct辅助修正；正max_hp_pct及其他RELIC_EXTRA_MODS不在本次范围。它们必须明确拒绝，不静默丢弃，后续天赋/特殊遗物接入时再确定计算规则。max_hp_pct不计为第19个可查询属性。

## 要做的

### 1. 独立属性容器
新增 `game/sim/combat/stat_block.gd`，StatBlock继承RefCounted：

```gdscript
func set_modifier(source_id: StringName, mods: Dictionary) -> bool
func remove_modifier(source_id: StringName) -> bool
func value(stat_id: StringName) -> float
func snapshot() -> Dictionary
```

- 默认基础值取Balance.STAT_BASE，cap取STAT_CAP，floor取STAT_FLOOR；无floor者最低0，无cap者不增加人造上限。生命最低10、护甲最低-20，其他字段被减益扣为负时按0。不要硬编码另一套属性表。
- 18个键：max_hp/hp_regen/lifesteal/armor/dodge/damage/melee_damage/ranged_damage/elemental_damage/attack_speed/crit_chance/area/move_speed/range/pickup_range/luck/income/max_energy。
- source_id是独立效果实例ID，不是遗物种类。两件玻璃大炮用不同source_id保留两份-0.25，同来源再次set是整体替换，不能意外累加；remove仅移除该来源，不存在返回false。
- 内部深拷贝传入mods，外部以后改原Dictionary不影响结果。snapshot是18字段有效值副本，调用方改它不改变内部。value查询非法属性时push_error并返回0，只在专门负向探针接纳精确错误。
- set在写入前完整校验：非空source_id，键必须为受支持的StringName，值只接受有限int/float（拒绝bool/字符串/NaN/INF）；max_hp_pct必须≤0。空mods可作为无效果来源；任何一项非法整个来源替换失败，原来源和值不变，不push_error。remove不存在同样是正常失败。
- 计算来源按source_id的字符串固定排序，输出字段顺序按STAT_BASE；字典插入顺序不同不能改变结果。可以在来源变化时重算缓存，不能只对已经截断的有效值继续加减，也不能永久损失被上限/下限遮住的部分。
- 不依赖Time/Node/Input/随机，不修改数据表，不读取资源文件或系统设置。

### 2. 接入Sim和移动
- PlayerState新增只读约定 `stats: StatBlock`，每局独立实例。外部只读Stats有效值，生产表现层不得调用其set/remove。
- Sim构造器签名保持兼容；旧initial_move_speed_bonus按RK012原约定先夹到0—1，再存为固定保留来源（例如&"initial_move_speed"），不能把这个兼容参数改变为无限原始值。此保留来源不可经外部命令set/remove；未知冲突返回失败。新来源一般规则仍保留未截断原始加减值。
- 新增Command.Kind.SET_STAT_MODIFIER/REMOVE_STAT_MODIFIER及字段modifier_source:StringName、stat_mods:Dictionary。Sim.apply成功修改仅返回一条SimEvent.Kind.STATS_CHANGED，entity_id=玩家0；失败返回COMMAND_FAILED且无部分写入、不改其他状态、ID计数器、索引或随机流。
- 成功set即使暂被cap遮住、有效值不变也保留原始来源并返回成功事件；相同来源整体替换。事件不传StatBlock或Dictionary引用，不提前实现泛型事件框架。
- 玩家自主速度从有效stats.value(&"move_speed")读取。保留PlayerState.move_speed_bonus作为现有调试界面的只读兼容镜像，构造及每次成功命令后同步，不保留两个独立真值。失败命令不改镜像。
- 其他17属性只完成存储/计算，不实现当前hp、能量消耗、护甲减伤、暴击、回复、吸血、拾取、升级抽样或遗物购买。生命上限变化不引入当前生命调整策略，留RK019确定。
- 不给敌人套玩家基础属性模型，不修改RK041敌人波次/追击/分离。

### 3. 自动测试
在 `game/tests/sim/`新增属性测试，按以下顺序汇报方法名：
1. 18字段默认值及确切键集合，与RK004数据独立参考一致；百分比0.05=5%、pickup_range以格计、无意外取整，两实例隔离。
2. 7个cap逐个超限截断：吸血0.25、闪避0.6、攻速3、暴击1、范围2、移速1、射程1；每个属性负值检查有效下限（生命10、护甲-20，其余0），无cap属性大正值保留，不假设所有属性都有上限。
3. 从RelicTable读取玻璃大炮mods，两个不同来源得到生命56.25、全局伤害0.6；固定生命+20后得到67.5。移除其中一个玻璃来源恢复90，再移除另一个恢复120；撤掉固定值恢复100。10份玻璃最低10，移除后可恢复，不能只倒除已经夹到10的值。
4. 原始汇总截断：移速来源0.8+0.8-0.9有效0.7；移除-0.9后1，移除其中一个0.8后0.8；负来源-0.3暂显示0，再加0.5应0.2。生命固定减到负且两份减益超过-100%也不出现负因子相乘反而回血，最低仍10。
5. 替换/移除、入参和snapshot副本隔离；同来源重复set不叠加，不同插入顺序结果逐字段一致；无效键/值、空来源、正max_hp_pct和其他extra_mod被拒绝，整个操作原子。初始保留来源不可外部改写。
6. Sim成功/失败事件及身份、随机流/敌人/索引不受影响；初始0/+50%和命令来源+50%分别60步64/96px，加成改到cap时128px；半幅/斜向、重放以及移除/替换后移动正确，兼容镜像与StatBlock一致。不直接写Sim状态做集成测试。
7. 完整 `python3 tools/run_tests.py`通过，旧断言不放宽。纯属性测试不依赖节点、实际时间或截图，全部测试仍满足architecture总时长要求。
