# RK-012 玩家移动

> 项目负责人已确认：WASD/左摇杆、0.2径向死区及模拟幅度、8px灰盒半径、最小Sim状态入口和可选初始移速加成，以及独立移动检查场景。

| 项 | 内容 |
|---|---|
| 优先级 / 里程碑 | P0 / M1，第4批 |
| 依赖 | RK-006（合并b7fe413）、RK-011（合并c7ff4fe），均通过；复用RK-003测试、RK-004数据和RK-073灰盒 |
| 分支 | `rk-012`，从最新main创建 |

## 目标
按backlog RK-012、architecture第3/4节及GDD 4.1/9.1，建立WASD/左摇杆→InputFrame→Sim.step→只读显示的位置更新链路。供后续RK-013镜头、RK-017武器和RK-019生命使用。

## 要做的

### 1. 数据和最小模拟入口
- 新增`game/data/player_config.gd`，PlayerConfig继承RefCounted，常量BASE_MOVE_TILES_PER_SECOND=4.0、BODY_RADIUS=8.0；像素换算复用ArenaConfig.TILE_PX。半径8是本任务灰盒约定，后续正式碰撞规格变更另审。
- 移速加成沿用Balance.STAT_BASE/CAP中的小数比例，0.5表示+50%，不是50。有效加成夹到[0,Balance.STAT_CAP[&"move_speed"]]，本任务只实现该属性的移动用途，不做RK-014通用属性系统。
- 新增`game/sim/core/input_frame.gd`（InputFrame，RefCounted），只含`var move_direction: Vector2 = Vector2.ZERO`；后续任务再加瞄准/射击字段。
- 新增`game/sim/entities/player_state.gd`（PlayerState，RefCounted），只读约定字段`position: Vector2`、`radius: float`、`move_speed_bonus: float`、`character_id: StringName`。新增`game/sim/core/run_state.gd`（RunState，RefCounted），只持有`player: PlayerState`。
- 扩展现有Sim，保留DT，持有只读约定`state: RunState`。构造接口`_init(seed_value: int, character_id: StringName, initial_move_speed_bonus: float = 0.0)`；初始位置ArenaBounds.play_rect().get_center()。支持knight/alchemist的标识，移动数值暂相同；不实现角色技能或其他角色属性。seed按原架构保留，可持有RunRng，不新增随机用途。
- `step(input: InputFrame) -> Array[SimEvent]`：将输入向量长度限制为不超过1，保留0—1的模拟幅度；按`4 * TILE_PX * (1+有效加成) * Sim.DT`位移，调用ArenaBounds.clamp_position约束整个玩家圆，写入state.player.position。无输入不移动，不做惯性，不取整逻辑位置，不接收渲染delta。
- 为保持架构返回类型，新增最小`game/sim/core/sim_event.gd`（SimEvent，RefCounted）；此任务step返回空的类型化事件数组，不虚构移动事件或提前实现其他事件类型。不实现apply/Command、波次、敌人、生命或存档。
- **已确认的接口限定**：架构原构造器只有seed/character两个参数；本任务增加可选初始移速加成参数，供独立验收构造+50%玩家。在RK-014/后续Command接入前不另设表现层直接修改状态的接口。项目经理已同步architecture，开发不改docs。

### 2. 输入采集
- 新增`game/view/battle/input_collector.gd`（InputCollector，RefCounted），公开`sample() -> InputFrame`；模拟层不调用Input，其他生产脚本不直接读移动Input。
- 允许仅在`game/project.godot`追加四项InputMap：move_left/right/up/down，对应物理A/D/W/S和左摇杆X负/X正/Y负/Y正，手柄device=-1。不覆盖已有设置，不加入射击/暂停等其他动作。
- 四项deadzone均为0.2，sample使用Input.get_vector四动作并显式deadzone=0.2，采用径向死区和重映射；不再次把非零结果normalized成满速。键盘对向相消，键盘/手柄共用动作，合成后长度不超过1。
- 0.2死区是负责人已确认的输入手感默认值；不做改键、设置保存、触屏、震动或设备提示UI。

### 3. 可运行的独立检查场景
- 新增`game/view/battle/player_view.gd/.tscn`：只读PlayerState，使用RK-073骑士idle第一帧及原pivot显示，位置与模拟中心对齐；不改旧资源，不实现完整动画状态机。模拟圆半径8，不把整张精灵画布当碰撞体。
- 新增`game/app/dev/player_movement_lab.gd/.tscn`：调试场景，复用ArenaView、InputCollector和正式FixedStepDriver，configure后再入树；固定步回调调用Sim.step，表现只读state同步。每个逻辑步采样输入；不在_process和_physics_process重复推进。
- 使用固定预览镜头居中竞技场，640×360可见中央部分；允许本调试场景的固定Camera2D，不跟随/前瞻/平滑，不提前做RK-013。场景内显示逻辑位置、步数、当前加成，可提供0/+50%两种构造重置按钮，重置时重建Sim及重置驱动；不通过改state绕过入口。
- 独立F6运行，不接boot和主入口；release无可用入口。不做常规HUD。图形输入探针可直接选择构造参数，不要求为测试提供生产状态修改接口。

## 测试
`game/tests/sim/`下自动测试只调用正式Sim入口，按顺序汇报方法名：
1. 初始位置/半径、空输入60步不移动；两实例互不影响，输入对象不被step改写。
2. 从中心沿四轴各60步：0加成64±0.01像素，+0.5加成96±0.01像素。
3. 四个斜向(±1,±1)各60步总距离与直线相同；幅度0.5的轴向输入60步32±0.01像素；向量(3,4)限幅后64±0.01像素，零输入无NaN。
4. 负加成按0、+1及超过+1按100%上限，结果分别64/128/128像素；测试参数只在构造时传入。
5. 四边四角长期移动，圆始终位于合法范围[40,40]—[1240,680]，相切允许；从墙边向内可立即离开。利用正式step反复移动，不直接给state赋位置制造结果。
6. 固定输入序列重复运行的最终状态相同；保留逻辑小数位置，不逐帧取整。
7. `python3 tools/run_tests.py`全量回归通过，旧测试不放宽；必要时给PlayerConfig常量补数据核对，不改通用测试运行协议。

## 独立运行验证
- 新增`tools/acceptance/rk012_probe.gd`及`rk012_verify.py`，Python3.9标准库，支持GODOT_BIN和任意cwd；先导入，每个Godot子进程timeout≤45秒；非零/超时/ERROR:/SCRIPT ERROR/标志缺失或重复均失败，唯一成功`RK012: passed`。
- 真实FixedStepDriver及Sim以30/60fps各运行1秒，分别记录实际时间、逻辑步数和位置，验证距离与`steps * Sim.DT * speed`一致，并满足backlog±2像素。驱动进程启动热身后reset再计数，不把加载耗时算作移动。使用固定注入InputFrame检查驱动，另做输入路径检查，不用测试标记替代正式玩家。
- 图形进程通过实际WASD键事件及InputEventJoypadMotion左X/Y轴事件，经过InputMap和正式collector，检查轴向、斜向、松开、反向相消、死区内0.1无移动、轴强度0.6重映射为约0.5、满推及手柄/键盘切换。无实物手柄时明确记录为合成轴事件，不能称为真机手柄试玩。
- Godot MCP启动调试场景、读运行输出并停止；读取实际状态证明输入→step→显示链路，必要时导出Godot实际截图，不在Python重画。纯位移指标以命令输出为主。

## 自检步骤
1. 完整回归、独立验证及图形输入检查通过，记录命令、输出、MCP结果和可运行场景路径。
2. 临时取消向量长度限制，斜向/超长输入测试失败；恢复。
3. 临时去掉Sim.DT或改用渲染delta，正式位移/限帧探针失败；恢复。
4. 临时不调用边界夹取，长期移动测试失败；恢复。
5. 临时把collector非零方向强制normalized，半推摇杆图形输入检查失败；恢复。
6. 恢复后重跑完整回归和独立验证，提交.uid与说明；按AGENTS格式逐条汇报，标清合成手柄事件和实物手柄测试的区别。
