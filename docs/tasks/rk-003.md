# RK-003 测试框架

| 项 | 内容 |
|---|---|
| 优先级 / 里程碑 | P0 / M1 |
| 依赖 | RK-002（已合并） |
| 分支 | `rk-003` |

## 目标
做出一条命令 `python3 tools/run_tests.py`。以后每个任务都用它自检，项目经理也用它验收。断言失败、运行时报错、卡死、违反分层规则，都必须判为失败，不能漏报。

## 要做的

### 1. 测试基类 `game/tests/lib/gd_test.gd`
- `class_name GdTest`，`extends RefCounted`
- 断言失败只记录，不中断：

  | 方法 | 通过条件 |
  |---|---|
  | `eq(actual: Variant, expected: Variant, msg: String = "") -> void` | `actual == expected` |
  | `near(actual: float, expected: float, eps: float = 0.0001, msg: String = "") -> void` | `absf(actual - expected) <= eps` |
  | `ok(cond: bool, msg: String = "") -> void` | `cond` 为 true |

- 每条失败记录写明：断言名、期望值、实际值、`msg`
- 提供 `get_failures() -> Array[String]`，运行入口和自测都用它

### 2. 运行入口 `game/tests/lib/run_tests.gd`
- `extends SceneTree`，用 `-s res://tests/lib/run_tests.gd` 运行
- 递归查找 `res://tests/` 下所有 `test_*.gd`。文件和方法都按名字排序，保证每次顺序一样
- 脚本加载失败或实例化失败：输出 `LOAD FAIL <路径>`，计 1 个失败。不能悄悄跳过
- 每个 `test_` 开头的方法都新建一个实例再运行（architecture 9.4 节：测试之间不共享状态）
  - 运行前输出 `RUN <路径>::<方法名>`
  - 运行后 `get_failures()` 为空计通过；不为空计失败，每条输出一行 `FAIL <路径>::<方法名> <失败记录>`
- 一个测试都没找到时计为失败，防止目录写错变成"0 个测试全部通过"
- 最后一行输出 `TESTS: <通过数> passed, <失败数> failed`。有失败 `quit(1)`，否则 `quit(0)`
- 注意：architecture 12 节记录过"脚本出错后进程不退出"。当时的探针是在 `_init()` 里出错，很可能是出错中止了这次调用，后面的 `quit()` 没执行到，主循环一直在跑。请把测试放在出错后仍能执行到 `quit()` 的位置，并按自检步骤 2 实测确认

### 3. `tools/run_tests.py`
- 按 architecture 9.2 节的 4 步依次执行。某一步失败就停下，后面的步骤不再执行
- 第 3 步（导入）限时 120 秒，第 4 步限时 300 秒。第 4 步的限时可以用参数 `--timeout <秒>` 改小，方便检查超时。超时要结束 Godot 进程，判为失败
- 第 3、4 步的判定：
  - 退出码不为 0
  - 超时
  - 有以 `SCRIPT ERROR` 或 `ERROR:` 开头的行（前面允许有空白）
  - 只对第 4 步：最后一个非空行不是 `TESTS: N passed, 0 failed`，或者 N 为 0
- 把判定写成纯函数，例如 `judge(step, returncode, output, timed_out) -> list[str]`，返回失败原因，空列表表示通过。这样可以单独写单元测试
- 失败时输出：哪一步失败、原因、相关的输出行。运行时报错要指出发生在哪个测试里，即报错行之前最近的那条 `RUN` 行
- 全部通过退出码 0，否则 1
- Godot 路径读环境变量 `GODOT_BIN`，默认 `/Applications/Godot.app/Contents/MacOS/Godot`。找不到时提示怎么设置，退出码 1
- 只用标准库，兼容 Python 3.9

### 4. `tools/lint_layers.py`
检查 architecture 第 3 节里能静态检查的规则。只扫 `game/sim/` 和 `game/data/` 下的 `.gd` 文件，`view/`、`app/`、`tests/` 不扫。

| 范围 | 报错条件 |
|---|---|
| `sim/` | `extends` 后面不是 `RefCounted`，也不是 `sim/` 或 `data/` 里声明的 `class_name`，也不是指向 `res://sim/`、`res://data/` 的路径。用白名单判定，不要列举 Node 的子类 |
| `sim/` | 出现 `Input.`、`Time.`、`OS.`、`FileAccess`、`get_tree(`、`signal `、`.emit(`、`.connect(`、`emit_signal(`、`randf(`、`randi(`、`randf_range(`、`randi_range(`、`randomize(` |
| `sim/` | 出现 `res://view/` 或 `res://app/` |
| `data/` | 出现 `res://sim/`、`res://view/`、`res://app/` |

- 没写 `extends` 的脚本默认继承 `RefCounted`，算合法
- 先去掉 `#` 注释再匹配，避免注释里提到这些词被误报。字符串里的 `#` 不算注释开头
- 关键字要整词匹配：`RandomNumberGenerator.randf()` 是 architecture 4.5 节允许的写法，不能误报，只有前面没有 `.` 的 `randf(` 才报
- 每条问题输出 `文件:行号: 规则说明`。有问题退出码 1，没有问题退出码 0
- 只用标准库，兼容 Python 3.9

### 5. 测试
- `game/tests/lib/test_gd_test.gd`：测 `GdTest` 自己。例如新建一个 `GdTest`，调用 `eq(1, 2)` 后 `get_failures()` 长度为 1；`eq(1, 1)` 后为 0；`near` 在误差内外各测一次；一个方法里连续两个失败断言记录 2 条。这些也保证 `main` 上至少有测试可跑
- `tools/test_run_tests.py`：测 `judge()`。每种失败条件至少 1 个用例，再加 1 个全部正常的用例。还要测：`ERROR:` 出现在行中间时不误判（例如 `print("NO ERROR: x")` 的输出），`TESTS: 0 passed, 0 failed` 判为失败
- `tools/test_lint_layers.py`：对临时目录里的样例脚本测上表的每一条规则，正反各至少 1 个用例。反例要包括 `rng.randf()`、注释里写 `Input.` 和 `extends RefCounted`

### 6. 文档（本任务允许改的 `docs/` 内容只有这两处）
- `README.md` 加"运行测试"一节：命令、`GODOT_BIN` 的作用、失败时怎么看输出
- `docs/architecture.md` 第 12 节：把"还没验证"的两项实测后写进表格，删掉"还没验证"这一句。两项是：
  1. 设置 `untyped_declaration=2` 后，推断类型 `var x := 1` 是否报警告或报错
  2. 某个测试方法运行时报错后，其余测试方法是否还会执行，进程能否正常退出
  
  如果实测结果和 architecture 其他章节的规定冲突，不要改那些章节，写在汇报里

## 不要做的
- 任何玩法代码和数据表（数据表是 RK-004）
- 第三方测试框架（GUT、gdUnit4 等）或 Python 第三方库
- 修改 `game/project.godot` 的设置。确实需要时先在汇报里说明原因

## 自检步骤
下面 1-5 步用到的临时文件，检查完都要删掉，不要提交。每一步都记下 `run_tests.py` 的退出码和关键输出，写进汇报。

1. **断言失败**：在 `game/tests/` 加一个测试方法，写 `eq(1, 2)`。退出码 1，输出里有对应的 `FAIL` 行
2. **运行时报错**：加一个测试方法，访问数组越界（`var a: Array = []` 后读 `a[5]`）。退出码 1，失败原因指出是这个测试方法。同一文件里放一个正常的测试方法，看它是否照常执行，结果写进 architecture 12 节
3. **卡死**：加一个死循环测试方法（`while true: pass`），用 `python3 tools/run_tests.py --timeout 20` 运行。20 秒左右判为失败，退出码 1。结束后用 `pgrep -fl Godot` 确认没有残留的无界面 Godot 进程
4. **解析错误**：加一个有语法错误的 `test_*.gd`。退出码 1。RK-002 验收时发现 `--check-only` 遇到解析错误退出码仍为 0，这一步确认运行器没有漏掉这种情况
5. **分层违规**：在 `game/sim/` 加一个 `extends Node` 的脚本。`lint_layers.py` 报错，`run_tests.py` 在第 2 步停下，退出码 1
6. **全部删掉后**：`python3 tools/run_tests.py` 退出码 0，最后一行是 `TESTS: N passed, 0 failed`，N > 0
7. `git status` 里没有残留的临时文件。Godot 为脚本生成的 `.uid` 文件要和脚本一起提交（RK-002 的 `boot.gd.uid` 就是这样）

## 验收标准（backlog）
- 加一个必然失败的断言，`run_tests.py` 退出码非 0
- 加一个运行时报错的测试，判为失败
- 加一个死循环测试，超时后判为失败
- 在 `sim/` 里写一处 `extends Node`，`lint_layers.py` 报错
- 全部删掉后通过
- `README.md` 写明运行命令
- 更新 architecture 第 12 节里"还没验证"的两项

项目经理验收时会自己重做第 1-6 步，另外再加几个本说明里没写的违规样例。
