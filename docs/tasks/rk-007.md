## 目标
按backlog RK-007、architecture 3/4.6/4.7及GDD第18节，提供不依赖节点的空间索引，供RK-010压测、RK-041敌人、RK-024索敌及RK-063障碍物使用。

本任务索引整数entity_id和二维中心点，圆形查询返回范围内的中心点ID。实体自身半径、阵营、最近目标、碰撞响应和分离行为由后续调用方处理；需要圆形实体重叠检测时，调用方扩大候选查询范围后再按双方半径精筛。本任务不创建Sim实体或接入战斗画面。

## 要做的

### 1. `game/sim/core/spatial_hash.gd`
`class_name SpatialHash`，`extends RefCounted`，全部公开接口有静态类型及`##`说明：

```gdscript
const CELL_SIZE: float = 64.0

func insert(entity_id: int, position: Vector2) -> bool
func remove(entity_id: int) -> bool
func move(entity_id: int, position: Vector2) -> bool
func query_circle(center: Vector2, radius: float) -> Array[int]
func has(entity_id: int) -> bool
func size() -> int
func clear() -> void
```

- CELL_SIZE为索引技术参数（像素），不是玩法射程，不写入数据表。此次固定64，不增加配置系统。
- 任意整数ID均可，包括0和负数；不同ID可在同一坐标。坐标为有限世界像素值，不夹取竞技场边界。调用方负责不传NaN/INF；本任务测试范围为坐标±4096、查询半径0—2048，另有负半径安全返回。
- `insert`：新ID插入成功返回true；已有ID返回false且保留原位置、数量和桶，不隐式覆盖。
- `remove`：存在则从桶和位置索引移除并返回true；不存在返回false。删除空桶，避免移动/借还反复留下空项。
- `move`：存在则更新位置，返回true；不存在返回false且不插入。同位置、同桶移动仍合法；跨桶要移除旧桶记录并加入新桶。
- `has/size`只读；`clear`清空全部索引，允许重复调用和随后重新插入。
- 点仅存入一个桶，键用`Vector2i`。每轴桶坐标为`floori(position轴 / CELL_SIZE)`，不得将负坐标直接截断到0，不拼字符串键。
- 圆查询先枚举包围方框覆盖的桶（上下限都包含），再按圆心距离平方`<= radius * radius`精筛。边界相切包含；半径0返回恰好同坐标的所有ID；半径负数返回空数组。
- 查询不得退化成每次遍历全部实体。用独立ID→位置索引支持移除、移动和精筛；禁止每次查询重建网格。
- 结果无重复，按有符号entity_id升序返回，与插入顺序、桶遍历顺序及移除重插历史无关。返回独立数组，调用方修改结果不能修改内部索引。
- 不依赖Time、OS、Node、物理、信号或随机源，不修改RunRng/Sim/竞技场函数。

### 2. 自动测试
`game/tests/sim/core/test_spatial_hash.gd`，继承GdTest。参考查询独立逐个遍历测试保存的点，不能调用SpatialHash内部方法生成期望。随机夹具使用`RunRng.new(20261030).spawn`；反向插入测试应复用同一份预先生成的数据，不因额外取数改变夹具。

汇报按下列顺序给出测试方法名及结果：
1. 空索引、has/size、插入、重复ID不覆盖、同位置多ID、删除及重复删除、clear后复用；覆盖0和负ID。
2. 格线两侧和负坐标：-64.001、-64、-0.001、0、63.999、64及二维组合；在格线附近做小圆和零半径查询。
3. 圆形精筛：圆心(0,0)、半径5包含(3,4)/(-3,-4)，排除(5.001,0)及方框内圆外的(4,4)；覆盖四象限、零半径、负半径、跨多个桶和覆盖全部点的大圆。
4. move的同位置、同桶、跨桶、多次正负坐标往返及不存在ID；每次核对旧位置已不可查、新位置可查、size不变。移动后再删除、重插，结果无残留重复。
5. 相同夹具用正序、逆序和删除重插顺序构建，查询结果逐项完全相同且升序；修改一次返回数组后再次查询，结果不受影响。
6. backlog主用例：1000个固定种子随机点，每轴[-1024,1024]，100次查询，圆心同范围、半径[0,256]，每次与逐点遍历的升序结果完全相同，不只比较数量。
7. 对第6项夹具进行固定的一批移动及移除，再做100次参考对照；记录数组同步更新，不借用被测对象读取期望位置。另测300个ID聚集同一点及清空后查询，确认不漏不重。
