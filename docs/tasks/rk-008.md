## 目标
按 architecture 第 6 节和 GDD 第 18 节，给弹体、伤害数字、拾取物提供共用的表现层节点池，实现容量有界、节点复用、归还隐藏和停用。不提前实现弹体运动/碰撞、掉落、经验或伤害数字。

本任务位于 backlog 第 6 节第 3 批，完成后解除 RK-045 的依赖，并为 RK-010、RK-051、RK-069 提供基础设施。模拟层不引用池，也不依赖表现节点是否申请成功。

### 本次已确认的口径
- “共用”指同一套池实现，各类场景分别创建池、各自配置容量，不把三种对象混在一个空闲列表里。
- 容量是硬上限；满池 acquire 返回 null，不扩容、不抢占活跃对象。这里只定义表现层申请失败，不据此删除模拟层弹体、拾取物或发放/取消奖励；未来使用任务负责补齐显示策略和具体容量。
- 对象池是表现层基础设施，但 backlog 明确要求测试。本任务限定允许离树节点池的自动测试；真实 SceneTree 的处理停用由独立 headless 探针验证，不改变通用测试运行器。

## 要做的

### 1. 可复用对象基类
新增 `game/view/battle/pooled_view.gd`，`class_name PooledView`，继承 Node2D。
```gdscript
var active: bool  # 只读约定，由池通过以下方法改变，初始 false
func activate() -> void
func deactivate() -> void
func _on_pool_acquire() -> void
func _on_pool_release() -> void
```
- 初始状态隐藏、process_mode=PROCESS_MODE_DISABLED；方法均有静态类型，公开接口有 `##` 说明。
- activate：active=true，调用自定义申请钩子，再显示并设 process_mode=PROCESS_MODE_INHERIT。
- deactivate：先 active=false、隐藏并禁用 process_mode，再调用自定义归还钩子。归还完成时必须仍是隐藏/停用状态，钩子不得重新激活对象。
- 两个钩子默认空实现，供未来子类清理 entity_id、变换、动画或其他表现状态。不要在本任务加入具体弹体/奖励字段。
- 入池场景根继承 PooledView，子节点必须继承父处理模式（INHERIT），不允许子节点自设 ALWAYS/WHEN_PAUSED、独立 CanvasLayer 或绕过 active 的外部处理回调。基类不用 set_process(false)/true 覆盖各子类原本的回调开关。
- 复用不依赖 `_ready()` 再次触发；每次借还都通过钩子。未来子类如使用 Tween/外部信号等独立活动，必须在归还钩子中结束或解除；本任务不实现通用异步资源追踪。

### 2. 单场景固定容量池
新增 `game/view/battle/node_pool.gd`，`class_name NodePool`，继承 Node；同名 `.tscn` 作为可实例化空池场景。
```gdscript
func configure(scene: PackedScene, capacity: int) -> void
func acquire() -> PooledView
func release(item: PooledView) -> bool
func get_capacity() -> int
func get_total_count() -> int
func get_active_count() -> int
func get_available_count() -> int
```
- configure 只允许入树前调用一次，合法输入为非空、根继承 PooledView 的 PackedScene 和正整数容量。非法配置 push_error 并安全返回，不保留部分初始化节点；已有配置不被替换。容量没有生产默认值。
- configure 预创建恰好 capacity 个场景实例，挂在池下面；所有实例初始空闲、隐藏、停用。不在每次申请/归还时 instantiate/free，不 reparent，不 queue_free。
- acquire 从空闲列表取一个，登记活跃状态并 activate；满池返回 null，不写 ERROR、不改计数。
- release 只接受本池当前活跃且仍有效的对象：调用 deactivate 后归还一次，返回 true。null、其他池对象、未借出的对象、重复归还都返回 false，原池及目标池状态不变，不写 ERROR。
- `total = active + available = capacity` 在配置成功后始终成立。get_total_count 指本池创建的场景根实例数，不含池根与场景子节点；完整子树节点数量也必须保持初始化后的固定值。
- 对象由池拥有，使用方只能 release，不能自行 free/queue_free、改父节点或跨池转移。不要求自动修复违反所有权约定导致的外部销毁。
- 用有类型的空闲/活跃集合，借还操作不扫描整个 SceneTree；不要求线程安全或任意时刻重配池。
- 不接入 boot、竞技场、固定帧驱动或 Sim。池销毁时由父子关系正常清理所有实例。

### 3. 测试夹具与真实处理探针
- `game/tests/view/battle/test_node_pool.gd` 继承 GdTest，测试离树的正式 NodePool/PooledView。属于本任务对 architecture 9.3 的限定例外；每个用例结束手动 free 池，不能泄漏节点。
- 如需夹具，放在 `game/tests/view/battle/fixtures/`：至少三个小型 PooledView 场景，分别代表弹体、数字、拾取物。只放测试 payload、借还钩子计数和处理计数，禁止实现玩法。含子节点的夹具用于验证整个子树。
- 新增 `tools/acceptance/rk008_probe.gd` 和 `rk008_verify.py`，包装器使用 Python 标准库、支持 GODOT_BIN 和任意 cwd、先导入，每个 Godot 子进程 timeout 不超过 45 秒。检查退出码、ERROR:/SCRIPT ERROR 和唯一通过标志，失败非零退出，成功 `RK008: passed`。
- 探针在真实 SceneTree 中实例化正式池/场景，对根及 INHERIT 子节点启用 `_process`、`_physics_process` 计数：借出并等待至少 8 个 process_frame 和 8 个 physics_frame，计数增长；归还后等待同样的帧数，两类计数不增长、不可见；再借出同一实例后计数恢复增长。
- 测量处理计数要在帧边界稳定后读取，避免 process_frame 信号在节点回调之前造成误判；不直接手调 `_process` 冒充引擎调度。
- 另验证一个重复利用实例的 `_ready` 只执行一次，而申请/归还钩子按借还次数执行。未借出的初始节点也必须在入树后保持隐藏、停止处理。
- 默认仅 headless 输出数值，不要求截图或美术资源。独立探针不加入常规 run_tests。

## 测试
汇报按顺序给测试方法名或探针输出：
1. 三种夹具分别用同一池实现配置容量 4；初始 total=4、active=0、available=4，每个实例均隐藏、停用，子树节点总数固定。
