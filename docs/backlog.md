## 0. 使用说明

### 0.0 分工
| 角色 | 由谁担任 | 职责 |
|---|---|---|
| 项目负责人 | 用户 | 定方向、拍板有争议的设计、试玩 |
| 项目经理 | Claude | 维护本文件和设计文档，给开发写任务说明，按验收标准验收 |
| 美术、开发和测试 | Codex（GPT） | 按 `AGENTS.md` 工作：按 style-bible 出图（PixelLab）并跑 `tools/art_check.py` 自检；按任务实现代码，写无界面测试；提交到任务分支 |

项目经理的工作流程见 `docs/pm-guide.md`。美术资源和代码都按第 0.3 节验收。风格锚点（RK-086）由项目经理验收后，再请项目负责人确认。

### 0.1 字段
| 字段 | 含义 |
|---|---|
| 编号 | 从 RK-001 起连续编号。任务删除后编号作废，不复用 |
| 优先级 | P0：不做就达不到本里程碑的退出标准，或会阻塞其他任务；P1：本里程碑应完成，可顺延到本里程碑末尾；P2：时间不够时可砍，或移到下一个里程碑 |
| 里程碑 | M1 原型 / M2 核心打磨 / M3 垂直切片 / M4 内容完整 / M5 外部打磨，对应 GDD 20 节 |
| 依赖 | 开工前必须已通过验收的任务。"—"表示没有前置任务；"M1 全部 P0 任务"指该里程碑其余所有 P0 任务。开工顺序见第 6 节 |
| 验收标准 | 项目经理据此判定通过或退回。写"测试"的，指 `python3 tools/run_tests.py` 运行的自动测试（RK-003） |

### 0.2 通用完成标准（每项都要满足，验收标准里不再重复）
1. 在独立分支上提交，分支名为任务编号，例如 `rk-012`
2. `python3 tools/run_tests.py` 通过（RK-003 完成前，按任务自己的验收标准检查）；代码符合 `docs/architecture.md`，验收按它的第 11 节
3. 数值来自 GDD 或 `game/data/` 数据表，代码里不写死数字
4. 美术资源通过 `tools/art_check.py`，并在 `art/ai_log.csv` 里有记录（纯手绘的，接口名填"手绘"）
5. 提交说明写清：做了什么、怎么验证、和 GDD 有出入的地方

### 0.3 验收流程
执行者提交 → 项目经理按验收标准逐条检查（默认用 Godot MCP 和无界面命令看运行输出；验收标准写了截图或录屏的，才看画面） → 结果为**通过**，或**退回**并写明不符合的条目。依赖的任务没有通过验收时，本任务不验收。退回的任务改完后重新提交，编号不变。

每个任务的进度记在 `docs/status.md`；退回意见写在该任务说明 `docs/tasks/rk-xxx.md` 末尾的"验收记录"里。
